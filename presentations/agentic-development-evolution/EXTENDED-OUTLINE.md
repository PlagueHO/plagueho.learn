## Extended outline

## 1. Agentic Development

**Visual:** A dark horizon with a single route: Complete → Delegate → Orchestrate → Scale.

**Message:** Agentic development is an adoption journey, not a catalogue of AI features.

**Speaker cue:** The destination is not more generated code. It is an engineering system where AI participation is repeatable, observable, governable, and shared across roles.

## 2. Four Moves

**Visual:** Four connected route markers.

**Message:** The talk moves through the market shift, repeatability, system scale, and expanded organizational flow.

**Interaction:** Each marker links to its section.

## 3. How Agentic Development Evolved

**Visual:** A seven-era timeline that reveals each capability and connecting line together.

**Narrative:**

- 2021: Code completion makes AI assistance ambient.
- 2023: GitHub Copilot Chat expands assistance from lines to conversations.
- 2024: MCP standardizes connected tools and context.
- 2025: Coding agents make work delegable.
- 2025: Agent Skills make repeatable work reusable.
- 2025: Multi-agent orchestration makes parallel agent work scalable.
- 2026: Hypervelocity Engineering extends AI participation across the delivery system.

**Speaker cue:** Each era expands the scope of delegated work and therefore increases the need for stronger operating controls.

## 4. Agentic Development: The Organizational Adoption Journey

**Visual:** A horizontal organizational maturity path with every stage centered on its connecting line. The Frustration and Business Barriers remain visible breaks.

**Stages:**

1. Individual Developer Productivity
1. Frustration Barrier
1. Context engineering
1. Skill Development
1. Plugins & Marketplaces
1. Governed Team Scale
1. Business Barrier
1. Hypervelocity Engineering

**Speaker cue:** The key maturity signal changes from code faster to learn and deliver faster together.

**Governed Team Scale:** Paved workflows, evaluations, observability, security policy, ownership, and adoption measures.

**Business Barrier:** The rest of the delivery organization must keep pace—product, operations, and security—and speed must remain tied to the customer outcomes that matter.

**Hypervelocity Engineering:** AI participation extends across roles and delivery stages through RPI, reusable patterns, shared guidance, and extensibility.

## 5. The Agentic Operating Model

**Visual:** A seven-layer stack.

| Layer | Purpose |
|---|---|
| Instructions | Always-on repository and path intent |
| Prompts | Reusable task entry points |
| MCP | Connected tools and context |
| Agents | Scoped specialist roles |
| Skills | Repeatable expertise bundles |
| Hooks | Deterministic lifecycle gates |
| Plugins | Portable combinations of the stack |

**Speaker cue:** The stack is the answer to "this is not delivering the outcomes I want." Keep this slide about composition. The improvement loop belongs on the next slide.

## 6. The Agentic Development Improvement Loop

**Visual:** A centered, readable sequence from intent to intended outcome, with a lower feedback arrow returning the intended outcome to the next intent.

**Loop:**

1. Prompt with the intended outcome and begin context engineering.
1. Connect MCP tools to get dynamic context.
1. Constrain by creating specifications and using hooks.
1. Observe with `/troubleshoot` and execution evidence.
1. Reuse successful behavior by building skills and sharing them with plugins.
1. Govern through policies and automated reviews such as GitHub Copilot code review.

**Speaker cue:** The loop matters more than any one tool. Evidence from each run improves the next one.

## 7. Context engineering

**Visual:** One segmented reference bar shows the four context types. Sparse and overloaded bars beneath it contrast too little and too much context.

1. Selected files steer the agent to the repository evidence relevant to this prompt.
1. Repository knowledge preserves specifications, ADRs, and plans through tools such as Spec Kit.
1. Organizational knowledge supplies governed standards, security guidance, and shared knowledge through Copilot Spaces.
1. Dynamic grounding uses MCP servers such as Microsoft Learn and WorkIQ for current product and enterprise context.

**Key line:** The engineer's job is not to add all context. It is to select the right context.

**Supporting note:** Repository instructions such as [`AGENTS.md`](https://docs.github.com/en/copilot/how-tos/configure-custom-instructions/add-repository-instructions) and [`copilot-instructions.md`](https://docs.github.com/en/copilot/how-tos/configure-custom-instructions/add-repository-instructions) make the right context reusable.

**Speaker cue:** Too little context forces assumptions. Too much context adds noise, cost, and distraction. Train engineers to find the smallest sufficient context set for the problem.

## 8. Developer leverage compounds through parallelism and autonomy

**Visual:** Five operating patterns sit directly on an exponential curve. Operating-model maturity increases on the x-axis; concurrent delivery capacity increases on the y-axis. The developer remains visible while agent lanes multiply, branch, form an autonomous Squad, and become multiple parallel Squads.

1. **Assist:** One developer and one agent work serially on one task.
1. **Delegate:** One developer uses several [custom agents](https://docs.github.com/en/copilot/concepts/agents/copilot-cli/about-custom-agents) serially on one task.
1. **Parallelize:** One developer distributes one task concurrently through [subagents](https://docs.github.com/en/copilot/concepts/agents/copilot-cli/about-custom-agents#running-agents-as-subagents) or [Fleet mode](https://docs.github.com/en/copilot/concepts/agents/copilot-cli/fleet).
1. **Orchestrate:** One developer oversees an autonomous [Squad](https://github.com/bradygaster/squad) with specialist roles, routing, and memory.
1. **Scale out:** One developer uses the [GitHub Copilot app](https://github.com/copilot) to oversee multiple Squads delivering multiple tasks or solutions concurrently.

**Executive takeaway:** The developer moves from doing work to directing systems of work.

## 9. Hypervelocity Engineering

**Message:** Developer acceleration is not the end state. It exposes the next constraint: the delivery system around engineering.

**Visual:** Agentic development crosses the Business Barrier into Hypervelocity Engineering, supported by three outcomes and a quiet four-ingredient foundation rail.

- Disciplined speed pairs AI acceleration with engineering rigor.
- Purpose keeps delivery focused on the right business and customer problems.
- Trusted context grounds decisions in reliable knowledge.
- Small expert teams, design thinking, production starting points, and AI across the lifecycle make the shift possible.

**Key line:** HVE is the next evolution in how multidisciplinary teams work with AI—not a product or final destination.

**Source:** [Microsoft: From Idea to Production](https://medium.com/microsoft/from-idea-to-production-ea25827a4274)

## 10. Five things every organisation should do now

1. Train every team in the Agentic Operating Model so everyone has a shared method for producing repeatable, governed outcomes.
1. Standardise maintained `AGENTS.md` and `copilot-instructions.md` guidance in every repository to align agents with organisational standards.
1. Govern access to organisational knowledge through approved MCP servers and Copilot Spaces, including secure access to Work IQ and other knowledge beyond the repository.
1. Empower every team to create, improve, and share reusable skills across team boundaries.
1. Create an organisational plugin marketplace where teams can easily discover, trust, install, and reuse approved skills, plugins, extensions, and hooks.

**Speaker cue:** These are organisational capabilities, not individual habits or a technology shopping list. Together they make agentic development accessible, consistent, secure, and reusable for every team.

## 11. What To Reach For Next

**Visual:** Five paired rows. Each pairs a frustration teams recognise with the fix that removes it, its icon, and a plain-language explanation of what changes.

**Speaker cue:** Pause for photographs. A skill is for the agent as much as the person. Connecting tools reaches organisational knowledge beyond the repository. Inconsistent output is an unconstrained agent. Large tasks need breaking down. Automate everything that can be automated, not just review.

**Message:** The destination is not faster developers. It is a faster organisation.

**Visual:** A widening wave carries AI-enabled capability from *Developer → Team → Delivery system → Organisation*.

**Speaker cue:** Agentic development begins with individual productivity, but Hypervelocity Engineering extends learning, decisions, and delivery across the whole value stream. Direct the audience to the dedicated Hypervelocity Engineering presentation for the operating practices that make this possible.

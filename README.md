## Presentations ([`presentations/`](presentations/))

Most presentations use Slidev. HVE also has a separate Reveal.js edition so the two versions can be developed side by side.

Browse the [published Presentations index](https://plagueho.github.io/plagueho.learn/).

| Presentation | Format | Source |
|---|---|---|
| Original Hypervelocity Engineering | Slidev | [Original deck](presentations/hypervelocity-engineering/slides.md) |
| Hypervelocity Engineering - *Why adding AI to the SDLC is not enough* | Reveal.js | [Source and run instructions](presentations/hypervelocity-engineering-ai-sdlc-is-not-enough/README.md) · [Published deck](https://plagueho.github.io/plagueho.learn/hypervelocity-engineering-ai-sdlc-is-not-enough/) |

Tag-based [GitHub releases](https://github.com/PlagueHO/plagueho.learn/releases) include one offline-ready ZIP file per presentation. The Slidev starter template is not included. Slidev assets use `<presentation>-<tag>.zip`; Reveal.js assets use `<repository>-<presentation>-<tag>.zip`. Each ZIP contains the built files and `serve.mjs` at its root.

Extract a presentation ZIP and run `node serve.mjs` in its folder. Open `http://127.0.0.1:3043` in a browser to present offline. No npm packages or Python installation are needed. See the [offline run instructions](presentations/hypervelocity-engineering-ai-sdlc-is-not-enough/README.md#run-a-release-offline).

### GitHub Copilot app tasks

The [repository app configuration](.github/github-app.yml) adds manual build and run tasks for all six Slidev decks and the standalone HVE Reveal.js deck. Review and accept the configuration in the app before use. No task runs automatically.

Install the existing root dependencies with `pnpm install` before using Slidev tasks. Follow the [Reveal.js setup instructions](presentations/hypervelocity-engineering-ai-sdlc-is-not-enough/README.md) for its separate dependencies. Tasks do not install packages or change package sources.

| Action | Task or app control |
|---|---|
| List decks and preferred ports | `Presentations: list` |
| Build all decks in sequence | `Presentations: build all` |
| Build one Slidev deck | `Slidev: build <deck-name>` |
| Run one Slidev deck | `Slidev: run <deck-name>` |
| Build or run the standalone Reveal.js deck | `Reveal.js: build HVE` or `Reveal.js: run HVE` |
| Display a running deck | The app opens the detected local URL in its integrated browser. Use the URL in the task output to reopen it. |
| Stop a running deck | Use the app's Stop control for that running task. Closing its browser view does not stop the server. |
| Check the Reveal.js deck | `Reveal.js: test HVE` |
| Check the task runner | `Presentations: test task runner` |

Each build writes to `presentations/<deck-name>/dist/`. The all-deck build stops at the first failure. Slidev run tasks use preferred ports 3030-3035 and reload source changes. The Reveal.js run task uses port 3043 and builds before serving; stop and restart it after source changes. If a port is already in use, stop the task that owns it or use the actual URL reported by Slidev.

The same runner works from a terminal:

```sh
node scripts/presentation-task.mjs list
node scripts/presentation-task.mjs build template
node scripts/presentation-task.mjs run hypervelocity-engineering-ai-sdlc-is-not-enough
node --test scripts/presentation-task.test.mjs scripts/slidev-process.test.mjs
```

See the [GitHub Copilot app repository configuration reference](https://docs.github.com/en/copilot/reference/github-copilot-app-reference/repository-configuration) for configuration review and browser URL detection.

## External development tools

Sensei and Impeccable are pinned Git submodules. Do not copy their source files into this repository or edit their source here. Fix external tool issues in the upstream project, then review and update the pin.

| Tool | Submodule | Upstream |
|---|---|---|
| Sensei | `.github/skills/sensei` | [spboyer/sensei](https://github.com/spboyer/sensei) |
| Impeccable | `vendor/impeccable` | [pbakaus/impeccable](https://github.com/pbakaus/impeccable) |

After cloning, initialize the pinned tools and restore the Impeccable skill link:

```sh
git submodule update --init --recursive
node scripts/link-impeccable.mjs
```

Impeccable documents a [submodule installation with tool-specific links](https://github.com/pbakaus/impeccable#installation). The committed `.github/skills/impeccable` link points to its GitHub Copilot build. The setup script restores that relative symbolic link on Linux and macOS. On Windows, it uses a directory junction without administrator permission.

Git can show the Windows junction as a local deletion of the symbolic link. Do not stage that deletion or replace the committed relative link with an absolute junction target.

To restore the normal Git placeholder before staging, remove only the junction with `node -e "require('node:fs').rmdirSync('.github/skills/impeccable')"`, then run `git restore -- .github/skills/impeccable`. Run the setup script again when you need the skill.

The existing Impeccable post-edit hook runs the pinned launcher under `vendor/impeccable`. Linking does not install or approve additional hooks. Review the hook before use. The launcher downloads its pinned engine when needed and verifies it against the submodule's checksum manifest.

To update a tool, select a reviewed upstream commit in that submodule, stage its changed pin, and run the setup script again. Do not use a moving branch during builds. Keep the four Impeccable agent definitions in `.github/agents` compatible with the selected pin. A submodule migration changes source ownership; it does not fix upstream vulnerabilities.

Squad runtime files, generated skills, agents, and workflows are not part of this repository. Authored learning content can still discuss Squad.
